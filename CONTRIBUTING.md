# Как внести вклад

Спасибо за интерес к проекту! Issue и pull request приветствуются.

## Разработка

Нужен **Node.js ≥ 20**.

```bash
git clone https://github.com/evilbruce666/1c-odata-mcp.git
cd 1c-odata-mcp
npm install
npm run build        # сборка TypeScript → dist
npm test             # юнит-тесты (без живой базы)
npm run lint         # ESLint
npm run format       # Prettier (форматирование)
npm run typecheck    # проверка типов
npm run manifest     # пересобрать инструменты в manifest.json из живого сервера
```

Перед PR прогоните локально то же, что и CI: `lint`, `format:check`, `typecheck`,
`build`, `test` — иначе CI не пройдёт.

## Тесты

- **Юнит-тесты** (`test/`, Vitest) проверяют чистую логику без обращения к 1С —
  билдер запросов, разбор конфигурации, классификацию метаданных, ошибки. Их
  достаточно для большинства правок.
- **Проверка на живой базе** делается вручную read-only probe-скриптами
  (`dist/scripts/probe-*.js`, запуск `node --env-file=.env …`) — секретов они не
  печатают. Для пишущих изменений тестируйте на **тестовой/копии** базы.

### Снимок схемы БП 3.0

Заглушки 1С в тестах легко написать «как кажется», а не как в настоящей конфигурации: тест
проходит, а на базе 1С отвечает, что поля нет. Поэтому в репозитории лежит снимок `$metadata`
типовой Бухгалтерии 3.0 — `test/fixtures/metadata/bp30.xml`: объекты, которые использует
коннектор, их табличные части и все перечисления (только схема, данных базы в нём нет).

- `test/metadata-snapshot.test.ts` прогоняет инструменты создания в режиме предпросмотра по этой
  схеме: каждое поле шапки и строк должно быть у объекта, а вид операции — среди значений
  перечислений. Новый инструмент записи — добавьте его в `CASES` этого теста.
- В своих тестах берите схему из снимка, а не пишите вручную: `bp30Metadata()`, `bp30Fields()` и
  `bp30Enums()` из `test/helpers/metadata-snapshot.ts`.
- Типичные расхождения, которые ловит снимок: в банковских документах контрагент составной
  (`Контрагент` + `Контрагент_Type`, поля `Контрагент_Key` нет); вид операции поступления от
  покупателя — «ОплатаПокупателя».
- Обновить снимок (например, после нового объекта в `src`):
  `npm run snapshot:metadata -- --db <имя базы>` — скрипт снимет `$metadata` и оставит только
  объекты, упомянутые в исходниках. Перед коммитом просмотрите дифф.

### Сверка записи после потерянного ответа

`test/write-reconciliation.test.ts` прогоняет каждый инструмент с `operationId`: предпросмотр →
подтверждение, на котором ответ 1С «теряется», → журнал и `write.operation.status`. В журнале
должен остаться способ сверки — назначенный `Ref_Key` (`prepareCreate` по умолчанию) или проверка
`check` (как число строк у правки документа). Без них статус после таймаута не отличит «не дошло»
от «создано» и посоветует повторить — так получаются дубли. Новый инструмент записи добавьте в
`ARGS` этого теста; тест упадёт, если инструмент с `operationId` в нём не описан.

### Живой прогон записи

Юнит-тесты не ловят то, что зависит от конфигурации 1С (так нашлись ложный отказ подтверждения
договора и поиск по метке, ломавший запрос). Перед релизом с изменениями записи прогоните все
инструменты создания и правки строк на настоящей (лучше тестовой) базе:

```bash
npm run test:live -- --db <имя базы> --yes          # ~1 мин
npm run test:live -- --db <имя базы> --yes --slow   # + сценарий «правка не дошла», ещё 2 мин
```

Прогон создаёт объекты с меткой `ZZ-TEST live …`, проверяет предпросмотр → подтверждение →
повтор, потерянный ответ и сверку `write.operation.status`, а в конце помечает всё созданное на
удаление (удалить физически — «Удаление помеченных объектов» в 1С). Нужны `READ_ONLY=false` и
`WRITABLE` для базы; журнал операций — во временном каталоге. Код возврата 1 — что-то не прошло.

## Стиль и коммиты

- Код форматируется Prettier и проверяется ESLint (в CI).
- Комментарии и сообщения для пользователя — на русском (целевая аудитория).
- Коммиты — в стиле Conventional Commits (`feat:`, `fix:`, `docs:`, `chore:`, `ci:` …).

## Идеи для вклада

- Поддержка других конфигураций 1С (УТ, КА, ERP) в аналитике.
- Дополнительные документы и справочники для записи.
- Тесты на новые модули.
